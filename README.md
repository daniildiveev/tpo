## Задание 1 — Функция arctg(x) через степенной ряд

### Что такое степенной ряд?

Представь, что ты хочешь посчитать `arctg(0.5)`, но у тебя нет калькулятора.  
Математики придумали хитрость: любую функцию можно приблизить **бесконечной суммой**:

```
arctg(x) = x - x³/3 + x⁵/5 - x⁷/7 + ...
```

Чем больше членов суммируешь, тем точнее ответ. Мы останавливаемся, когда очередной член стал **меньше 0.0000000001** (epsilon).

### Три ветки алгоритма

```
|x| > 1  →  используем хитрость: arctg(x) = π/2 − arctg(1/x)
            (заменяем большое число на маленькое и считаем ряд для него)

0.5 < |x| ≤ 1  →  ещё одна хитрость: arctg(x) = π/4 + arctg((x−1)/(x+1))
                   (при x=1 ряд сходится ОЧЕНЬ медленно — миллиарды членов,
                    поэтому сначала уменьшаем аргумент до числа < 0.5)

|x| ≤ 0.5  →  считаем ряд напрямую (быстро сходится, хватит ~50 членов)
```

### Что тестируем? (41 тест)

| Группа тестов | Что проверяем | Пример |
|---|---|---|
| Точные значения | arctg(1) = π/4, arctg(0) = 0 | math.pi/4 |
| Нечётность | arctg(−x) = −arctg(x) | для x = 0.5, 1, 2, 100 |
| Непрерывность | ответ не «прыгает» на границе ветвей | x = 0.9999 vs 1.0001 |
| Тождество | arctg(x) + arctg(1/x) = π/2 | для x = 2, 5, 1000 |
| Сходимость | результат совпадает с `math.atan` до 6-го знака | много значений x |
| Большие x | arctg(1 000 000) ≈ π/2 | |
| Маленькие x | arctg(0.0000000001) ≈ 0.0000000001 | |
| Параметр epsilon | при грубом epsilon результат менее точный, но не неверный | |

## Задание 2 — HeapSort с «характерными точками»

### Что такое HeapSort?

**Сортировка кучей** — способ упорядочить список чисел.  
Работает в два шага:

1. **Построить кучу** — переставить числа так, чтобы самое большое оказалось вверху (как в пирамиде).
2. **Вытаскивать вершину** — снять самое большое, поставить на конец, починить пирамиду, повторить.

### Характерные точки (КТ)

Мы «пронизали» код метками — как флажки на трассе. Каждый раз, когда программа проходит флажок, она записывает это в список `trace`.

| Метка | Где стоит | Когда срабатывает |
|---|---|---|
| **CP1** `SORT_ENTER` | Вход в `heap_sort()` | Один раз, всегда |
| **CP2** `BUILD_HEAP_DONE` | После построения кучи | Один раз, всегда |
| **CP3** `HEAPIFY_ENTER` | Вход в `_heapify()` | Каждый вызов просеивания |
| **CP4** `HEAPIFY_SWAP` | Перед заменой элементов внутри кучи | Только когда нарушен порядок |
| **CP5** `EXTRACT_SWAP` | После извлечения максимума | n−1 раз |
| **CP6** `SORT_EXIT` | Выход из `heap_sort()` | Один раз, всегда |

### 6 наборов данных и их трассы

#### `[]` — пустой список
```
CP1 → CP2 → CP6
```
Никакой работы нет: сразу вошли и вышли.

#### `[1]` — один элемент
```
CP1 → CP2 → CP6
```
Один элемент — уже «отсортирован», ничего делать не нужно.

#### `[2, 2, 2]` — все одинаковые
```
CP1 → CP3(узел=0, размер=3) → CP2
    → CP5(i=2) → CP3(0,2)
    → CP5(i=1) → CP3(0,1)
    → CP6
```
CP4 **ни разу не срабатывает** — одинаковые числа не нужно менять местами.

#### `[3, 1, 2]` — корень уже максимум
```
CP1 → CP3(0,3) → CP2
    → CP5(2) → CP3(0,2)
    → CP5(1) → CP3(0,1)
    → CP6
```
При построении кучи замен не было (3 уже стоит на вершине).

#### `[5, 4, 3, 2, 1]` — уже является кучей
```
CP1 → CP3(1,5) → CP3(0,5) → CP2
    → CP5(4) → CP3(0,4)→CP4(0↔1)→CP3(1,4)→CP4(1↔3)→CP3(3,4)
    → CP5(3) → CP3(0,3)→CP4(0↔2)→CP3(2,3)
    → CP5(2) → CP3(0,2)→CP4(0↔1)→CP3(1,2)
    → CP5(1) → CP3(0,1)
    → CP6
```
Куча строится без замен. Все CP4 появляются **только при извлечении**.

#### `[4, 10, 3, 5, 1]` — многоуровневое просеивание
```
CP1 → CP3(1,5)
    → CP3(0,5)→CP4(0↔1)→CP3(1,5)→CP4(1↔3)→CP3(3,5) → CP2
    → CP5(4) → CP3(0,4)→CP4(0↔1)→CP3(1,4)→CP4(1↔3)→CP3(3,4)
    → CP5(3) → CP3(0,3)→CP4(0↔1)→CP3(1,3)
    → CP5(2) → CP3(0,2)
    → CP5(1) → CP3(0,1)
    → CP6
```
CP4 срабатывает **и при построении кучи, и при извлечении** — самый богатый путь.

### Что тестируем? (59 тестов)

- Для каждого из 6 наборов: результат правильно отсортирован ✓
- Для каждого из 6 наборов: трасса CP совпадает с эталонной ✓
- Структурные инварианты (для всех 6 наборов сразу):
  - Первый элемент трассы всегда CP1
  - Последний элемент всегда CP6
  - CP2 встречается ровно 1 раз
  - CP2 всегда стоит до первого CP5
  - CP4 всегда следует сразу за CP3
  - Количество CP5 = n − 1
  - Исходный массив не изменяется (работаем на копии)

## Задание 3 — Доменная модель по тексту

### Исходный текст

> «После того, как толпа вновь разразилась ликующими криками, Артур обнаружил, что он скользит по воздуху к одному из величественных окон во втором этаже здания, перед которым стоял помост, с которого оратор обращался к народу.»

### Кто и что есть в этом тексте?

```
Здание (Building)
  └── Этаж №2 (Floor)
        └── Величественное Окно (Window, is_magnificent=True)
              └── Помост (Platform)  — стоит перед окном
                    └── Оратор (Speaker) — стоит на помосте
                          └── .address(Народ) → "Оратор обращается к народу."

Артур (Arthur)
  └── .slide_toward(Окно) → скользит к величественному окну по воздуху

Толпа (Crowd, size=500)
  └── .erupt() → is_cheering = True
```

### Правила модели (бизнес-логика)

| Правило | Почему |
|---|---|
| `Floor.number ≥ 1` | Этажи нумеруются с 1, не с 0 |
| `Crowd.size ≥ 0` | Отрицательная толпа — абсурд |
| `Crowd.erupt()` только если `size > 0` | Пустая толпа не может кричать |
| `Arthur.slide_toward(w)` только к `is_magnificent=True` | В тексте — «величественные окна» |
| `Speaker` требует `Platform` | Оратор должен где-то стоять |
| `Platform` требует `Window` | Помост стоит перед конкретным окном |

### Что тестируем? (59 тестов)

| Группа | Что проверяем |
|---|---|
| Создание сущностей | Все 8 объектов создаются с правильными атрибутами |
| Валидация | Неверные аргументы → `ValueError` или `TypeError` |
| Целостность связей | `Window → Floor → Building` — цепочка не рвётся |
| `Arthur.slide_toward` | Устанавливает цель, флаг `is_sliding`, отклоняет не-величественные окна |
| `Speaker.address` | Возвращает строку с именами оратора и аудитории |
| `Crowd.erupt` | Меняет `is_cheering` с False на True; пустая толпа — ошибка |
| Полный сценарий | Собираем всю сцену из текста и проверяем всё разом |
| Граничные случаи | Этаж 1 (минимум), много окон, большая толпа |
